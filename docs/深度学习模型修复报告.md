#### 2. 关键发现

Debug日志暴露了问题：
```
[DEBUG] Prediction result columns: 
  ['target_0_probability', 'target_1_probability', 'target_prediction']

[WARNING] Unknown output format!
[WARNING] Using fallback column: target_0_probability  # ❌ BUG在这里！
```

### 🐛 Bug详情

**文件**: `run_analysis.py`  
**位置**: `PyTorchTabularOVRWrapper.predict_proba()` 方法

**问题代码**:
```python
# 原始代码（有BUG）
if 'prediction' in res.columns:
    # ...
elif '1_probability' in res.columns:
    # ...
else:
    # 走到fallback，错误处理！
    prob_cols = [c for c in res.columns if 'prob' in c.lower()]
    probs[:, 1] = res[prob_cols[0]].values  # prob_cols[0] = 'target_0_probability'
    probs[:, 0] = 1 - probs[:, 1]           # 然后取反，完全错了！
```

**问题**:
1. 代码没有explicit检查`target_0_probability`和`target_1_probability`
2. 走到fallback逻辑，使用第一个概率列（`target_0_probability`）
3. 将class 0的概率赋值给class 1的位置，然后取反
4. 导致预测概率完全颠倒！

---

## ✅ 修复方案

### 代码修改

在if-elif链的**最前面**添加explicit检查：

```python
# 修复后的代码
if 'target_1_probability' in res.columns and 'target_0_probability' in res.columns:
    # ✅ 直接使用正确的列
    print(f"[DEBUG] Using 'target_0_probability' and 'target_1_probability' columns")
    probs[:, 0] = res['target_0_probability'].values
    probs[:, 1] = res['target_1_probability'].values
elif 'prediction' in res.columns:
    # ...其他格式
```

**修改位置**: `/mnt/t2-6tb/Linpeikai/Shenxian_work_doc/run_analysis.py` 第510-515行

## 💡 关键经验教训

### 1. Debug日志的重要性
详细的debug日志直接暴露了概率提取的问题，否则很难发现这个隐蔽的bug。

### 2. 验证集不是万能的
虽然添加了验证集，但如果预测概率本身就是错的，验证集也无法修正这个问题。

### 3. 模型输出格式的多样性
不同版本的`pytorch_tabular`可能返回不同的列名格式：
- `1_probability` / `0_probability`
- `class_1_probability` / `class_0_probability`  
- `target_1_probability` / `target_0_probability` ← 我们的版本

需要在代码中显式处理每一种可能性。

### 4. Fallback逻辑的风险
Fallback逻辑虽然提供了兼容性，但容易掩盖真正的问题。应该优先使用explicit检查。
